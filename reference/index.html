    SqlGrounder ¶

    Bases: Protocol

    ground(sql, tables, graph, probe, repair=False) ¶

    Verdicts on the column-to-column joins of sql.

    tables is keyed by the reference as the query writes it (an unqualified name has an empty source). Only joins where a column is a known key are judged; a join on anything else is business logic the graph was never meant to model. A column that cannot be attributed to exactly one table is left alone: missing information never flags.

    With repair, a verdict that has exactly one safe fix is applied and marked repaired, and the returned SQL is checked again. What is left in unresolved could not be fixed; the caller decides whether such a query may run.

    Ports: reading what a database was asked before, and mining it for expressions.

    ExpressionChecker ¶

    Bases: Protocol

    Holds an expression a reviewer wrote to what a measure may be.

    check(expression, columns) ¶

    expression as the engine will run it, and the columns it reads.

    columns maps the table's column names to their kinds (type_kind: int, float, bool, str, date, ...). The expression is what goes inside an aggregate, over those columns only: no subquery, aggregate, window or parameter, and something that can be added up.

    Raises:

    Type Description
    MeasureError

    Saying what is wrong with it.

    ExpressionMiner ¶

    Bases: Protocol

    Finds the reusable scalar expressions in a statement.

    mine(sql, dialect, columns) ¶

    Expressions in sql (written in dialect) over one known table each.

    columns maps each table of the catalog to its column names; an expression is returned only when every column it reads can be placed in exactly one of them, and when it holds no parameter, subquery, aggregate or window. A statement that does not parse yields nothing.

    SemanticCompiler ¶

    Bases: Protocol

    Generates the SQL that answers a semantic query.

    compile(query, tables=None) ¶

    SQL for query, reading each table from tables or its own name.

    tables maps a table to where it actually lives in the store — a slice, usually, whose name encodes the rows it holds. The compiler writes those names in directly rather than emitting the original name and having someone rewrite it afterwards: the SQL is generated for the store's dialect, and re-parsing it under a neutral one rewrites string literals and drops quoting.

    Implementations must emit a single SELECT statement that passes SqlValidator.validate, quote every identifier, and never inline a value that did not come from the query's own literals.

    compile_joined(query) ¶

    SQL for a query whose dimensions or filters read referenced tables.

    One flat SELECT joining along query.joins, naming every table by its own name: unlike compile, the result goes through the query pipeline, which loads what it reads, applies the caller's row rules and masks to each table and records the access.

    SQL identifiers and parameters¶

    Centralized SQL identifier validation and quoting.

    Every dynamic identifier (table or column name) that gets interpolated into a SQL string MUST pass through :func:sanitize_identifier / :func:quote_identifier. Values are always sent as bound parameters and must never go through these helpers. Keeping this logic in one place avoids divergent, weaker copies (e.g. str.replace-based "sanitizers") across adapters.

    What a reviewer certifies¶

    Business terms: what people call a table, its columns and the values they hold.

    A term is written by a model once per table and then reviewed, like the rest of the catalog. Until someone certifies it, nothing reads it: the semantic model, the question planner and the published context all take certified terms of an approved catalog and nothing else.

    ColumnAttribute ¶

    Bases: BaseModel

    The words for one column, and for the values it stores.

    MeasureError ¶

    Bases: ValueError

    A measure a reviewer wrote that cannot be one, with the reason why.

    SqlAttribute ¶

    Bases: BaseModel

    A measure that is an expression over one table's columns.

    Certified separately from its term: an expression decides what a number means, which is a bigger claim than a synonym.

    Term ¶

    Bases: BaseModel

    One business concept: a name, the words for it, and where it lives.

    attribute(table, column) ¶

    The words for table.column, if the term has any.

    certified_sql(table) ¶

    The expressions on table a reviewer signed off.

    carry_over(fresh, previous, columns) ¶

    fresh terms, with the certified ones of an earlier catalog kept as they were.

    A certified term is a reviewer's work, and re-analysing the database must not replace it with a new guess. It is kept when every table it covers is still there, minus the columns that are not. columns maps each table of the new catalog to its column names.

    clean_words(words, *avoid) ¶

    Words as a model or a person wrote them, made usable.

    Not a list becomes none; blanks, repeats and the name itself are dropped.

    The proof gate: a repaired statement differs from the original by one literal.

    When a condition compares a column with a value it does not hold ('Premium' where the data says 'premium'), the fix is to swap that one string. Whoever proposes the fix, a rewriter here or a model elsewhere, is not trusted to have changed only that: the candidate runs only if this proves it. After the literal-repair gate in NVIDIA Auto Ontology.

    Parser-free, like the rest of sql_text: the check must not depend on a candidate being something a particular parser round-trips.

    prove_substitution(original_sql, candidate_sql, absent, present, validate) ¶

    Whether candidate_sql is original_sql with absent replaced by present.

    True only when all of these hold: the original had the literal absent; the candidate has present everywhere the original had absent and is otherwise the same literals in the same order; with literals blanked the two statements are identical; and validate (the guardrails every query passes) accepts the candidate. Only string literals are covered.

    split_literals(sql) ¶

    sql with every string literal blanked, and the literals in order.

    Quoted identifiers stay in the skeleton: a candidate that renamed a column is not the same statement.
